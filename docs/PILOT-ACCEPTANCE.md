# Mahabharata collaborative pilot: acceptance contract

Requested 10 September 2026. This is a delivery target, not a description of completed features.

1. The project lead can invite a real collaborator; both accounts see the same mission and accepted history. Public source publication is separate from granting access to the running site.
2. A local model proposes modular work from a broad mission brief. The lead can edit, reject, and approve the proposal. Nothing is assigned or executed merely because AI proposed it.
3. Modules have explicit inputs, outputs, dependencies, and acceptance criteria. Contributors claim approved tasks and share reviewable results with provenance.
4. The founder is the initial mission lead. They can assign and revoke subdivision leads. A subdivision lead can approve only their own scope, with server-enforced permissions and recorded decisions.
5. At least two contributors can opt in with local workers. Jobs are leased, bounded, cancellable, recoverable, and published idempotently. Credentials are never shared between contributors.
6. Blender, local Ollama, and Unreal each have a tested operation on this PC. Unreal must produce a validated scene or playable preview, not merely appear in a list. Engine installation and license acceptance may need the owner.
7. Task outputs refer to exact inputs and accepted Git revisions. Parallel work is isolated; reviewed integration preserves ancestry and detects stale or conflicting work.
8. A complete vertical slice goes from approved AI plan to independently contributed assets, integration, human review, and an accessible result. Test with real collaborators before describing the system as ready for large teams.

## Working order

- Preserve implementation and revised manifesto in Git; prepare an independent export and public GitHub repository.
- Add AI planning proposals and lead approval with modular task records.
- Add scoped subdivision leadership and community membership management.
- Connect approved tasks to local work and reviewed outputs.
- Implement a durable opted-in worker queue, then a second-worker trial.
- Add and test Unreal integration, then run the complete collaboration trial.

Existing capabilities and remaining limitations are recorded in FUTURE-CHANGES.md. Capacity alone is not a reason to claim this contract complete.
